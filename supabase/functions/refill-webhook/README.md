# Refill webhook — not deployed

This prototype accepts RevenueCat POST events only after checking a configured authorization header. It recognizes the iOS refill product in sandbox, one unit at a time. It resolves only a single unambiguous `qahwa:<Supabase UUID>` identity and queues the event through the service-only `enqueue_refill` RPC. A separate service-only `process_refill_inbox` RPC credits the ledger. The handler attempts a fast batch after queueing; a database worker is scheduled every five minutes to retry pending events. Unrelated products receive 200; invalid authorization receives 401; supported-product events requiring review and inbox errors receive 503. No request bodies or credentials are logged.

Required function secrets: `REVENUECAT_WEBHOOK_AUTH`, `SUPABASE_URL`, and the Supabase-provided `SUPABASE_SERVICE_ROLE_KEY`. The RevenueCat integration must send the same authorization header. Never put either secret in the app or Git. JWT verification must be disabled for this function because RevenueCat authenticates using the configured header instead.

This prototype must not be deployed for paid purchases yet. The inbox retains accepted events and can retry database failures, but alerting and recovery for failures that occur before an event reaches the inbox are not set up; `REFUND_REVERSED`, multiple quantities, account transfers and reconciliation are deliberately rejected for review. The app does not yet assign the `qahwa:<UUID>` RevenueCat identity or redeem credits. Test with authenticated sandbox events and replay failures before enabling refill purchases. RevenueCat's webhook feature may depend on its plan; check the account's actual entitlement and cost before activation.

Run local tests with `npx tsx --test supabase/functions/refill-webhook/events.test.ts supabase/functions/refill-webhook/index.test.ts`. To exercise the actual handler and checkpoint client's outgoing HTTP requests, start `postman simulation run postman/simulations/refill-inbox.sim.yaml --port 4317 --no-history`, then run `npx tsx --test supabase/functions/refill-webhook/simulation.test.ts src/utils/sandboxCheckpoint.simulation.test.ts` and stop the simulation. It uses only dummy data and Postman stand-ins, not Supabase; its assumptions and limits are recorded in `postman/simulations/refill-inbox.context.yaml`. These checks do not test deployment, real RevenueCat events, deployed server authentication or the real network-to-ledger boundary. The provisional webhook HTTP contract is in `openapi.yaml`.
